# Architecture

The MV3 service worker owns the WebSocket to Atlas and routes messages to the YouTube Music content script. The content script reads the actual HTMLMediaElement and player bar, parses byline artist and album separately, and ignores short incomplete DOM/media transitions. It listens for media `volumechange`, including after media replacement. Unknown volume is `null` and remains unavailable to the tablet until observed on real media. On replacement, the last observed lower volume is applied to a fresh element that defaults to 1.0 before adopting it. Newly inserted media elements are prepared before they play. For explicit Galaxy volume commands the worker also calls the YouTube Music player’s dedicated volume setter in the page main world; the real media element remains the authority for state reports. A reset to 1.0 on the same element is rejected unless an explicit 100% desktop or Galaxy selection authorized it; selecting a lower volume cannot authorize a later reset. Player bar duration is confirmed when available, so a streaming media element whose duration grows with playback cannot churn track identity. Autoplay waits until the new track's media clock restarts before publishing its metadata and position together. When duration remains unknown, Atlas searches by title and full artist and rejects ambiguous recording lengths; metadata remains visible throughout. Exact album and duration lookup and focused searches find songs beyond LRCLIB's first search page, while locally scored duration matching excludes alternate cuts that would desynchronize lyrics. LRC offset tags adjust the lyric timeline. Atlas retries provider failures for the same track, cancels retries on track change, and accepts one active source, owns a versioned snapshot, fetches and caches LRCLIB line timed lyrics, and broadcasts snapshots to display clients. The display has a single persistent page with a state machine and local monotonic playback interpolation. It shows artwork and metadata while lyrics load or remain unavailable, and title and artist remain visible even when cover loading fails. Timed lyrics fade in when found. Only trusted user gestures can send slider changes through a dedicated validated `SET_VOLUME` message through Atlas and the worker to the media element; `SOURCE_STATE` reports the authoritative `volume` and `muted` values back. Commands return an ACK for delivery only; actual playback and volume are confirmed by subsequent source state.

Protocol v3 is in `shared/protocol.ts`. A source HELLO optionally carries the extension build for Atlas diagnostics; `1.0.5` is this release. Only validated messages cross role boundaries. A source disconnect invalidates interpolation, and a new source starts with a blank snapshot. The simulator uses a loopback source connection, never production display UI. An updated extension build and YouTube Music tab reload are required when upgrading from v2.
